# MongoDB-style leakage comparison: independent review

Stopped by user decision. The committed `report-ko.md` is a partial report generated by `report-partial.py` from already completed files. Missing cells are unmeasured. No experiments were resumed after cancellation. `report.py` is the unexecuted full-matrix integration draft; its completion assertions intentionally do not pass for the stopped run.

Memory and file evidence only. No database connections, product modifications, or new fixture generation. Shared encoders and attack runners belong to the other workers; these files recompute and review their outputs.

Run from the repository root after the input artifacts finish:

```text

rtk proxy npx tsx bench/mongo-reeval/v-astra/verify-ab.ts
rtk proxy npx tsx bench/mongo-reeval/v-astra/verify-cd.ts

rtk proxy npx tsc -p bench/mongo-reeval/v-astra/tsconfig.json
```

`source-provenance.py` records official source revisions and hashes through HTTP; it does not copy licensed source. The rules document fixes the revision used for review. Rerunning source discovery later does not establish that a later source has identical behavior.

`verify-models.ts` independently recomputes C-port SHA-256 tags and uses observed query keys with WebCrypto HMAC/AES-CTR to enumerate C-mongo tags. It checks all 20,000 input rows' shapes, with cryptographic checks on smaller field samples. This validates the leakage model, not MongoDB SDK byte compatibility.

`verify-ab.ts` independently replays all public shape predictions. Other index-only attack aggregates are arithmetic-checked and witness-scored, not replayed in full. `verify-cd.ts` rescores every saved prediction, checks plaintext query hit sets, and replays unknown-label inference and selected phone searches. `verify-delta.ts` independently replays two-endpoint shape attacks; it does not rebuild every opaque ESC ciphertext. `verify-strong.ts` independently derives the dictionary reduction and checks public-reference ambiguity witnesses.

An optional `--partial` flag on A/B, delta, and strong checks permits inspecting finished subsets and records `partial: true`. The final report refuses those partial check results and requires all 48 C/D files, all 12 A/B and 12 delta files.

Results are in `bench/results/2026-09-30-mongo-reeval/v-astra`. Historical performance is recalculated from saved artifacts, never newly measured here. The report explicitly distinguishes a plaintext-counter PostgreSQL prototype, an idealized encrypted-state leakage model, and actual MongoDB implementation channels not reproduced (ordered BSON arrays, full logs, intermediate compaction, and ECOC ciphertext contents).
