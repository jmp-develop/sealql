# 1억 행 AND·OR 조합 추가 측정

대상: 고객 1억 행, 단일 테이블의 기존 `scale-matrix.ts` 조건 5개. 원본 10만 행을 ID만 바꿔 1,000벌 복제했으므로 값도 1,000번씩 반복된다. 실제 일치 건수는 원본 평문 COUNT × 1,000이며 1억 행 평문 COUNT와 일치함을 확인했다. 로컬 합성 fixture의 결과이며 운영 성능 보장이 아니다.

| 사례 | 조회 방식 | 대상 행 수 | 실제 일치 건수 | 결과 행 수/오류 | DB 후보 수 | 평문 SQL ms | 전처리 ms | 제품 DB ms | SQL 사이 ms | 후처리 ms | 제품 합계 ms | SQL 호출 수 |

- `findMany`: 평문과 제품 모두 ID 오름차순 한 페이지 200행, 여섯 암호 필드 같은 투영. 예열 2회 후 교차 7회, 각 열의 중앙값. 모든 성공한 제품 행의 ID·필드 값이 평문과 같았다. 지표별 중앙값은 서로 합산되지 않을 수 있다.
- `count`: 각 경로 1회. 제품 `maxCandidates=1,000,000`; 내부 검색 예산은 API 상한(요청당 후보 20,000, 수신·복호화·결과 각 32MiB, 30초, 배치 2,000)을 사용했다. 오류의 소요 시간과 코드도 원본 JSON에 기록했다. DB 쿼리 자체가 30초를 넘으면 전체 시간은 30초보다 길 수 있다.
- 시간은 Node 드라이버에서 측정한 SQL 요청~응답 왕복이다. 전처리는 호출 시작~첫 SQL 요청, SQL 사이는 연속 SQL 왕복 사이, 후처리는 마지막 SQL 응답~호출 종료다. DB 후보 수는 PostgreSQL이 드라이버에 반환한 행 수 합계이며, 오류 종료 전까지의 수다. plain SQL ms는 평문 한 SQL의 왕복 시간이다.
- 측정 동안 평문·보조 테이블 autovacuum을 꺼 두고, 완료 직후 복구했다. 평문은 VACUUM ANALYZE, 보조 테이블은 ANALYZE만 수행한 상태였다. 보조 테이블 VACUUM 생략은 제품에 불리한 조건이다.
