# 강화 검색 성능 및 일반 모델 버전 비교

완료: **전체 완료**. 일반 14질의, insert 1,000행, prepareAllSearch 1,000행, 강화 102/102 조건, 평문 대조 3480회. 

전제: 일회용 DB 127.0.0.1:56439만 사용했고 `disposablePool` 내부 `assertDisposable`·사용자·데이터 디렉터리·포트를 먼저 확인했다. 코디네이터가 다른 DB 작업이 없음을 확인해 독점 순서로 실행했다. 원본 `bench_realistic_100k`를 읽기만 했으며 파생 전용 스키마는 마지막에 삭제했다.

비교 대상은 별도 git worktree에서 빌드한 **v1.1.1**과 **4c83aae**이며 제품 코드·문서 수정과 커밋은 없다. 일반 14질의는 동일 부모·companion 물리 테이블과 키·salt·도장을 두 버전이 읽는다. 원본과 ID를 조인한 기존 현재 형식 파생 fixture를 복사했고 처음 100행 6필드 인증 복호화(600필드)를 원본과 대조했다. 강화 비교는 같은 모델·필드·키·scope·행 결속 및 동일 stampKey 유도를 유지해 암호문·salt·도장을 복사하고 해당 강화 토큰 열을 생략했다.

강화 비교의 1만/10만은 **별도 물리 부모·companion의 실제 행 수**다. 전화 강화 모델은 일반 이름과 강화 전화, 이름 강화 모델은 강화 이름과 일반 전화다. 목록은 ID순이고 이름·전화 2필드를 투영하며 매 반복 ID 순서·두 원문 값, count를 평문 및 메모리 기준과 대조한다. 일반 14질의 목록은 README와 같이 6필드를 투영한다. SUM/AVG는 암호화 이름의 조건으로 고른 **평문 points**만 계산한다.

조회·insert: 첫 측정 1회 별도 기록, 예열 2회, 경로 순서를 번갈아 교차 7회 중앙값. SQL 요청~응답은 드라이버 Client.query 왕복 합계이며 서버 실행 시간만이 아니다. 전체 시간은 API 시작부터 결과까지다. ±MAD는 반복값의 중앙 절대 편차이며 표의 SQL·전체 중앙값은 서로 합산하지 않는다. OS 캐시는 비우지 않았으므로 첫 측정을 콜드 캐시라고 부르지 않는다.

¹ 코디네이터가 시간 제한에 맞춰 prepareAllSearch를 원본에서 파생한 **1,000행·6필드**로 축소 승인했다. 예열 1회·교차 3회로 별도 표기하며 10만 행 재구축 성능이나 분산으로 외삽하지 않는다. 10만 행 재구축은 중단한 초기 실행을 제외하고 미측정이다. insert는 같은 원본 1,000행을 두 전용 모델에 관리형 쓰기로 넣고 매번 트랜잭션을 롤백했으며, SQL에는 API 안의 쓰기 SQL만 포함하고 외부 롤백은 제외했다.

² 판정은 |두 전체 중앙값의 차| ≤ 두 경로의 MAD 합이면 “반복 변동 범위 안”으로 표시한 기술 통계다. 7회(prepare는 3회)와 한 세션으로 무영향을 증명하는 통계적 동등성 시험은 아니다. 최대·최소·표준편차와 각 반복값은 raw.json에 보존했다.
