# 필드별 GIN과 다중 컬럼 GIN 비교

2026-09-27 · 일회용 PostgreSQL `127.0.0.1:56439` (`.local/pg-test`) · 고객 100,000행. `assertDisposable`로 DB 데이터 디렉터리·소유자·포트를 확인한 뒤 실행했다. `bench_standard_next_100k`의 기본·건너뜀 companion을 각각 두 복사본으로 만들었다. 모든 토큰 열과 값, 정확 일치 B-tree는 같고, 부분 검색 열 여섯 개의 색인만 **열별 GIN 여섯 개** 또는 **다중 컬럼 GIN 하나**로 다르다. 원본 데이터·제품 `src/`는 수정하지 않았다.

## 실행 계획·저장 공간

[`explain.json`](explain.json)은 직접 후보 SQL을 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`으로 각 한 번 실행한 원시 계획이다. `AND 4` 기본에서 필드별 색인은 두 GIN의 `BitmapAnd`(39.72 ms), 다중 색인은 GIN 하나(7.21 ms)를 사용했다. 건너뜀 `AND 4`는 필드별 색인에서 GIN 하나와 많은 heap 재검사(76.10 ms), 다중 색인에서 GIN 하나(8.80 ms)를 사용했다. `AND 6` 기본은 필드별 GIN 네 개와 정확 B-tree의 `BitmapAnd`(19.81 ms), 다중 GIN 하나와 정확 B-tree의 `BitmapAnd`(11.29 ms)였다. 건너뜀 `AND 6`은 필드별 GIN 네 개(19.04 ms), 다중 GIN 하나(10.95 ms)였다. 이는 직접 후보 SQL의 한 번 실행이라 위 공개 API 중앙값과 동일한 측정은 아니다. 전체 계획과 블록 수는 원시 파일에 있다.

| 변형 | 필드별 companion 총 B | 다중 companion 총 B | 필드별 GIN 합계 B | 다중 GIN B |
|---|---:|---:|---:|---:|
| 기본 | 184,844,288 | 184,860,672 | 33,800,192 | 33,808,384 |
| 건너뜀 | 278,052,864 | 278,175,744 | 59,179,008 | 59,301,888 |

총 크기는 `pg_total_relation_size`로 테이블과 모든 색인을 포함한다([`storage.json`](storage.json)). CTAS로 만든 별도 복사본을 비교한 값이며 원본 companion의 총 크기나 017 D의 통합 배열 저장량과 직접 동일하지 않다. 정확 B-tree와 PK는 두 복사본에 모두 있다.

## 관리형 쓰기와 필드 추가

같은 원본 평문 1,000행을 사용해 별도 쓰기용 부모·companion에 공개 API `insert`, `memo` 부분 `update`, `delete`를 각각 1,000회 실행했다. API가 암호화와 토큰 생성을 수행한다. 기본은 필드별→다중, 건너뜀은 다중→필드별 순서로 측정하고 두 번째 순서에서 입력 행 순서를 뒤집었다. 수정 값 검색 20행과 삭제 후 부모 행 0건을 단언했다. 아래는 단건 지연 중앙값(ms); 총합과 각 1,000회 원시는 [`write.json`](write.json)에 있다.

| 변형 | 색인 | insert | memo update | delete |
|---|---|---:|---:|---:|
| 기본 | 필드별 | 4.92 | 1.80 | 0.48 |
| 기본 | 다중 | 5.85 | 1.56 | 0.44 |
| 건너뜀 | 필드별 | 7.79 | 1.81 | 0.43 |
| 건너뜀 | 다중 | 7.70 | 1.77 | 0.44 |

필드 하나 추가는 빈 `bigint[]` 열을 복사본에 잠시 추가한 다음, 필드별 구성에서는 새 열 GIN 하나를 만들고 다중 구성에서는 기존 여섯 열과 새 열을 포함한 **대체 다중 GIN**을 새로 만드는 방식으로 흉내 냈다. 기존 색인은 측정 중 유지했고 새 색인을 만든 뒤 제거했다. 빈 열이므로 새 필드의 실제 토큰 적재·backfill 비용은 포함되지 않는다.

| 변형 | 새 필드 GIN 생성 ms | 대체 다중 GIN 생성 ms |
|---|---:|---:|
| 기본 | 53.91 | 1,538.52 |
| 건너뜀 | 74.49 | 2,724.03 |

원시는 [`rebuild.json`](rebuild.json)에 있다. 실제 운영 스키마 변경은 기존 다중 색인 교체, 잠금/동시 쓰기, 데이터 채움 절차가 추가되므로 이 수치만으로 산정할 수 없다. 모든 수치는 로컬 합성 fixture의 관찰이며 운영 성능 보장이나 보안 인증이 아니다. 이 실험은 토큰 값·열을 바꾸지 않았으므로 새 누출 표면을 도입하는 구조 변경을 측정한 것은 아니지만, 공격 시뮬레이션을 새로 실행하지도 않았다.
