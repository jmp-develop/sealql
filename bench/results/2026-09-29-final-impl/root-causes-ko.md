# 지정 7조건 원인 분리

제품은 변경하지 않았다. 락을 잡고 보호 표를 읽기만 했으며, 함수 입력은 임시 표에 복사했다. 명령은 `node --import tsx bench/final-return/root-causes.ts`(exit 0)이다. 근거는 [전체 계획·함수 통계](root-causes.json), [함수 변형 계획](root-focus.json), [원본 재실행](root-focus-warm.json)이다.

아래에서 수치는 **연구 → 제품**이다. 버퍼는 루트 노드의 shared hit/read 블록이며 자식 값을 중복 합산하지 않았다. 호출 수는 `track_functions=pl` 통계 차이로 실제 측정했다. 함수 1회 비용은 동일한 연구 행 배열을 두 함수에 넣은 2회 예열·7회 교차 중앙값(µs)이다. 각 literal의 coarse 후보를 ID순 최대 1,024개(푸른달은 101개) 복사했으므로 전체 후보 분포나 긴 불일치 비용의 대표값은 아니다. EXPLAIN은 단회 진단이며 기존 교차 중앙값을 대체하지 않는다.

제품·연구 토큰은 descriptor가 달라 같은 평문·bits=2라도 충돌 집합이 같지 않다. 이를 맞추려고 키·비트를 바꾸는 것은 제안하지 않는다. exact equality를 제품이 `coalesce(proof,false)`로 감싸는 것도 연구와 다르며, zero_and_common2의 계획 행 추정은 연구 7, 제품 병렬 스캔 작업자당 602다. 이것이 병렬 선택에 기여했을 가능성은 있지만, 표현만 바꾼 계획 대조 전에는 확정하지 않는다.

4b가 목록 시간을 절반으로 줄였다는 해석은 성립하지 않는다. sub_mid의 세 계획은 같은 Bitmap Heap Scan 16,574행 + 정렬 + 재조회이며, 첫 제품 실행 shared read 14,471블록이 뒤 no-SET 실행에서 1블록으로 줄었다. 원본을 마지막에 다시 실행해도 sub_mid 49.34→27.25ms, starts 43.14→24.50ms가 됐다. 같은 배열에서 no-SET은 원본과 거의 같았다(세종대로 10.19→10.17µs, 서울 starts 5.50→5.64µs). 여러 물리 clone을 섞은 순환 측정에서 같은 표를 연이어 읽는 함수 변형의 예열 이득을 함수 변경 효과로 볼 수 없다. checks-off의 동일 배열 이득은 별도로 약 9–15%였다(세종대로 10.19→9.24µs, 서비스 상담 14.50→13.02µs, 서울 starts 5.50→4.67µs).

수정 전 제안:

1. `coalesce(proof,false)`를 제거한다. 현재 predicate는 WHERE 아래 양의 AND/OR뿐이므로 NULL과 false는 모두 행을 제외한다. 불필요한 포장을 없애면 PostgreSQL이 exact equality 선택도를 직접 볼 수 있다. NULL·중첩 Boolean 회귀를 확인하고, count의 부모 제거/유지 계획을 다시 비교한 뒤 채택한다. count를 일괄 companion-only로 바꾸는 것은 memo 275.88→603.43ms 퇴행 때문에 지금 채택하지 않는다.
2. 목록 fallback은 연구의 후보→판정→LIMIT으로 통일하고 proof 재조회와 OR 전용 경로를 제거하는 기존 4d 방향을 유지한다. 단, 부분 측정에서 and2_or_and2 52.01→146.42ms 퇴행이 있으므로 위 표현 정리와 함께 비교한 뒤 적용한다. quick는 흔한 목록 이득 때문에 유지한다; 특정 연산자/조건명 예외를 추가하지 않는다.
3. 함수는 SET search_path를 유지한다. 제거의 독립 이득이 확인되지 않았다. 손상 입력 검사 제거는 동일 배열에서 실제 이득이 있으므로 종료를 normalized length로 제한하면서 적용 후보로 삼되, 전진 커서·이진 탐색은 긴 근접 불일치에 필요한 교정이라 유지한다. 두 알고리즘을 갈라서 단순 값만 특별 취급하지 않는다.
4. MAIN·꼬리 키 색인·bits는 현재 유지한다. 현재 7조건으로는 전역 변경의 이득을 입증하지 못했고, coarse exact 조건에서 꼬리 키 색인의 이득이 이미 관찰됐다.

검증 한계: 첫 실행은 SQL 캡처 오류 경로에서 드라이버가 연결을 폐기하여 세션의 track_functions 설정도 사라졌고 호출 통계가 비었다. [실패 기록](root-causes-initial-no-stats.json)을 보존한 뒤 실제 실행 연결에서 설정하여 진단을 다시 수행했다. 따라서 EXPLAIN은 최초 실패분을 포함하면 두 번이며, 표는 통계가 수집된 재실행만 사용한다. 함수 통계 시간은 병렬 작업자의 합이므로 벽시계 시간보다 클 수 있다. 함수 입력 비교는 모든 경로의 참/거짓 집계가 같음을 확인했지만 새로운 제품 변경이나 전체 최종 게이트는 실행하지 않았다. 로컬 fixture 결과이며 운영 보장·보안 인증이 아니다.
