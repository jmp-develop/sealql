# 선택 원문 삽입 공격: 세 저장 방식 비교

**확실:** 이 시험에서 현재 제품은 R9 이전과 같은 수준으로 선택 삽입 공격에 노출됐다. 같은 scope에 알려진 값을 쓰고 그 행의 후보 토큰을 읽을 수 있으면, R9 이전에도 토큰의 의미를 학습해 전화번호를 조립할 수 있다. 위치 도장이나 검색 질의 키를 얻지 않아도 가능한 공격이다. **모름:** 단일 키·표본·공격 알고리즘의 결과로 세 방식의 보안 강도를 일반적으로 순위 매길 수는 없다.

## 조건과 공격자 경계

- 기존 fixture 100,000행을 읽기만 했다. 고정 순열에서 참조 10,000행, ID가 겹치지 않는 피해 1,000행을 골랐다. DB 적재·수정, 제품 코드 수정은 없다.
- 비교: `f9005bd`의 R9 이전 후보 토큰, 연구 최종안, 현재 제품. 각 방식의 실제 구현과 토큰을 30개씩 대조했으며 다른 scope의 제품·이전 토큰도 60개 대조했다.
- 공격자는 참조 평문, 자신이 삽입한 평문과 해당 행의 후보 토큰, 피해 행의 후보 토큰·암호문에서 드러나는 바이트 길이를 안다. 제품·연구의 정규화 길이도 사용한다. 원본 키, 질의 키, 피해 정답은 예측기에 제공하지 않는다. 정답은 채점에만 사용한다.
- 두 전략을 각각 N=10/100/1000으로 실행했다. `whole-values`는 참조의 완전한 값을 쓰고, `packed-pieces`는 참조에서 얻은 2글자 조각을 한 행에 묶는다(정규화 길이 최대 256). 후자는 임의 텍스트 입력 허용을 가정하며 앱의 전화번호 검증 등을 우회한 결과가 아니다.
- 알려진 삽입 행들의 토큰 출현 비트열과 평문 조각 출현 비트열을 대응시킨다. 고유하게 대응하는 조각만 라벨링한다. 알려진 값의 토큰 집합 일치, 참조 사전·길이·빈도 추정, 전화번호의 인접 조각 그래프와 skip 제약을 사용한다. 그래프 탐색 상한은 행당 2,000상태다.
- 다른 scope에서는 전체 토큰의 직접 전이를 검사했다. 전이되지 않는 토큰의 부재를 평문 부재로 오해하지 않도록 값 예측은 삽입 없는 참조·길이 기준선으로 돌아간다. 따라서 다른 scope의 표는 모든 공격을 실행한 최대 복원율이 아니라 **직접 라벨 전이 0 + 독립 기준선**이다.

## 해석과 저장 형식의 대가

**확실:** 전화번호에 대한 높은 복원은 위치 도장 도입 이전에도 나타난다. 기존 [질의 관찰 보고서](../../2026-09-29-attack-extra/report-ko.md)의 전화 `0 → 87.5%`는 그 보고서의 후보 사전 공격과 위치 키 관찰 공격을 비교한 값이지, 후보 토큰만 이용하는 모든 공격의 상한이 아니다. 이번 선택 삽입·그래프 공격은 더 강한 별도 공격 조건이다.

**확실:** 같은 알려진 값을 두 번 처리한 제품 위치 도장 18쌍에서 salt가 달랐고 도장 겹침은 0이었다. 이 시험은 삽입 행의 도장을 피해 행으로 그대로 옮겨 조각을 식별하지 못했다. 후보 토큰의 행 간 안정성이 이번 공격의 직접 원인이다. 원시 도장에 대한 다른 분석이나 암호학적 안전성을 증명한 것은 아니다.

**추정:** 세 방식의 작은 차이는 토큰 도메인 변경에 따른 16비트 충돌 양상, 연구의 추가 단어 경계 조각, 공개 길이가 함께 영향을 준다. 특히 ASCII 전화번호 길이는 R9 이전도 암호문 바이트 길이에서 알 수 있어 새 정규화 길이의 이득이 없다. 연구의 낮은 전화 복원율을 연구 방식이 일반적으로 더 안전하다는 증거로 해석하지 않는다. 충돌로 같은 출현 서명이 합쳐지면 이 고유 대응 공격의 라벨링이 실패하기 때문이다.

| 변경 후보 | 이번 공격에 대한 효과 | 대가·미검증 |
|---|---|---|
| 기존 scope 경계를 공격자와 피해자 사이에 적용 | 직접 토큰 라벨 전이 0을 확인 | 같은 scope에 쓰기가 허용되면 효과 없음; scope 분할은 공유 검색 의미와 권한 설계에 영향 |
| 후보 토큰까지 행별 무작위화 | 행 간 안정된 토큰 라벨 전이를 없앨 수 있음(추정) | 현재 공통 GIN 조회가 성립하지 않아 행별 판정·다른 검색 구조 필요; 재암호화/재색인·성능 비용 미측정 |
| 토큰 비트 수 축소 | 충돌 증가로 고유 라벨링을 어렵게 할 가능성 | 후보 증가와 판정 비용, 다른 공격의 재식별 가능성은 별도 측정 필요; 이 보고서만으로 권장하지 않음 |
| 도장 salt 갱신·키 길이 증가 | 안정된 후보 토큰에 대한 이 공격 원인은 유지 | 선택 평문과 후보 토큰의 대응 자체를 없애지 않음 |

**모름:** 정확 검색·현재 사용성·성능을 모두 유지하면서 이 공격을 막는 저장 형식 변경은 검증하지 못했다. 앱의 쓰기 권한과 입력 검증은 관찰 가능한 선택 입력을 줄이지만 암호 형식의 해결책은 아니다. DB 백업만 가진 공격자에게 선택 입력 권한이 자동으로 주어지는 것도 아니다.

## 재현·검증·한계

실행: `node --import tsx bench/final-review/r9-impl/run.ts --size 1000`. 실제 완료 출력은 `COMPLETE bench/results/2026-09-29-final-review/r9-impl/active-1000-both.json`이다. [원시 결과](active-1000-both.json)는 234개 결과 행, `complete: true`, 원본 검증 30/30/30, 다른 scope 검증 60, salt 검증 18을 기록한다. 예측기와 정답 채점은 함수 인자로 분리했다.

10만 확대, 여러 키·seed, 실제 서비스 입력 승인 절차, 질의 관찰과 결합, exact 전용 프로필, 전체 위치 도장 암호 분석, 완전한 그래프 탐색은 미검증이다. 랜덤 기준선은 동일 참조 사전에서 무작위 값을 뽑으며 제품 성능을 측정한 실험이 아니다. 실제 개인 정보 대신 기존 fixture를 사용한 기계적 시뮬레이션이다.

관련 공격 계열: [Zhang·Katz·Papamanthou, USENIX Security 2016](https://www.usenix.org/conference/usenixsecurity16/technical-sessions/presentation/zhang). 논문은 파일 삽입에 의한 질의 복원 공격을 다룬다. 이번 시험은 안정된 후보 토큰의 출현 서명과 알려진 삽입 평문을 대응하는 시험이며 논문 전체의 재현이라고 주장하지 않는다.
