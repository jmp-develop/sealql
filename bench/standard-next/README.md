# Standard core 100k verification

These scripts preserve historical experimental records. They import the removed repository API and cannot run against the current native Drizzle API. Their existing results under `bench/results/` remain evidence for the version measured; use `bench/verify-core/` for current verification preparation.

Run only against the owned disposable cluster at `127.0.0.1:56439`. Every DB script calls `assertDisposable` and checks the port before using SQL. The source `bench_realistic_100k` schema is read only. The derived `bench_standard_next_100k` schema is the only fixture written.

1. `rtk proxy node --import tsx bench/standard-next/load.ts` creates the product DDL tables and loads all 100,000 customers and tickets. The parent ciphertext uses the product sealer; companion arrays use the product piece and token functions. Batched SQL inserts reduce round trips. The skip variant copies the same authenticated ciphertext because its model and field codec are identical, then computes a distinct companion profile. A numeric argument limits the number of 100-row batches for a smoke run. Repeated runs resume by ID.
2. `rtk proxy node --import tsx bench/standard-next/verify-all.ts customers` and the same command with `tickets` authenticate all six fields against source plaintext and check row counts. Run this before timing. The first run's output is `verify-customers-tickets.json` when no table is passed.
3. `rtk proxy node --import tsx bench/standard-next/matrix.ts`, then `count.ts`, `join.ts`, `mixed.ts`, `crud.ts`, `storage.ts`, and `db-attack.ts`. `matrix.ts` accepts an optional case-name regex for a smoke run. The scripts assert exact ID order and projected field values before and during seven alternating measured rounds.
4. The previous-algorithm columns (`old-matrix.json`, `old-join-mixed.ndjson`) were measured in the same session with a separately built copy of the removed earlier product code and its matrix/JOIN harness. That code is not preserved, so those columns cannot be reproduced; only the results are kept. `old-oracle.ts` recomputes the earlier token format for scoring only.

The C locale makes Korean plaintext `LIKE` a full scan; those ratios do not establish a general speedup. `token-attack.json` uses the independent public review corpus and its existing mechanical scorer. `db-attack.json` uses actual old and new companion arrays on a synthetic template fixture, with the same 20,000 victim rows, 20,000 reference rows, 5% known rows, and seed 99. The latter is an attack lower bound and is less representative of natural text than the review corpus.
