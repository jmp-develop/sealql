# SealQL current state and code map

For `search` positions containing text, one additional SQL request per nonempty candidate batch verifies strict increase using the database column collation; malformed ordering raises `INVALID_CANDIDATE_SHAPE`. UUID and integer positions retain the in-process check without an extra request. Transactionless drivers raise `UNSUPPORTED_DRIVER` before managed write or reindex callbacks run.

As of 2026-09-27, the product has one search mode: `standard` HMAC pieces, PostgreSQL companion GIN/B-tree indexes, and internal authenticated predicate verification. Stateful search, V2 posting pages, and bucket search are rejected research lines ([decision 011](decisions/011-rejected-research-lines.md)). They are not product modes.

The public database integration is `sealql/drizzle/v0.45`. `createSealed({ sealer })` provides encrypted field builders, `register(table, { row, scope? })`, managed `insert/update/upsert`, `open/openRaw`, `findMany/count/search`, and `reindex`. The parent and returned companion are ordinary Drizzle tables and both must be exported to drizzle-kit. SealQL does not wrap `drizzle()` or the driver. The former raw PostgreSQL export, repository binding API, and row revision have been removed. Read the [integration guide](llm-integration.md) and [examples](../examples/standard-consumer.ts).

The app supplies a fixed 32-byte global key and may supply fixed model keys. No key version or DB policy table exists. AES-GCM binds a field to model, field ID, codec, key scope, scope, and row ID. Derived field and token-profile keys are cached; row values, plaintext, ciphertext, and frequency information are not retained in server-lifetime caches. The companion stores one row per `(scope,row)`. Exact token columns use B-tree expression indexes and substring columns share a multicolumn GIN index. The parent has no search tokens or trigger. A partial managed update changes only affected token columns, while a parent delete cascades. Scope-free tables use `_` consistently in AAD, tokens, and cursors.

Search first asks PostgreSQL for token candidates, then authenticates condition fields before opening selected fields for matches. A call-scoped cache avoids repeated authentication for duplicate 1:N JOIN rows. `m.sql` permits ordinary SQL conditions inside Boolean matches, including OR with encrypted conditions. `findMany` and `search` use keyset cursors; in `search`, the first table listed in `match` sets the page order, and a one-to-many JOIN requires a unique many-side keyset. `count` returns an exact number or `LIMIT_EXCEEDED`. Candidate, byte, deadline, and cancellation budgets bound requests; a short page retains a cursor after the last fully processed row. There is no offset pagination or encrypted field range, sort, or DB aggregate support. A cursor spans separate requests and is not a snapshot. Plain Drizzle encrypted-column writes raise `SEAL_REQUIRED`; raw SQL encrypted-column writes bypass token maintenance and can cause omissions, repaired by `reindex`. Managed writes omit `undefined` properties. UUID and text row IDs, text scopes, and scope-free companions pass drizzle-kit generate, migrate, and repeated push; text row comparisons and keyset ordering follow the database column collation and can use its indexes.

Implementation: [`src/core/`](../src/core/) holds the cipher, token generation, predicate compiler, candidate SQL, and cursor; [`src/adapters/drizzle/v0.45/`](../src/adapters/drizzle/v0.45/) holds builders, registration, writes, reads, search, and reindex. The active fixture-derived tests are [`test/standard-drizzle.test.ts`](../test/standard-drizzle.test.ts), [`test/standard-postgres.test.ts`](../test/standard-postgres.test.ts), and [`test/standard-types.ts`](../test/standard-types.ts). The former `standard-postgres` test name is retained for continuity; it tests the Drizzle API. Package compilation and installation are checked by `npm run build`, `npm run check`, `npm test`, and `npm run test:install`. Post-change V1–V3 verification of the native API is complete: [V1 correctness](../bench/results/2026-09-27-native-verification/v1/report-ko.md), [V2 token equality and constant-scope attack](../bench/results/2026-09-27-native-verification/v2/report-ko.md), [V3 performance](../bench/results/2026-09-27-native-verification/v3/report-ko.md). Decision [013](decisions/013-drizzle-native-api-implemented.md) records the shipped API and its implementation-time deviations from the original plan. Historical performance and attack reports from before this API (`2026-09-27-core-verification` and earlier) are not measurements of it.

**Security status:** keyless database theft resistance for full records is unproven. The database sees deterministic token frequency and co-occurrence, ciphertext length, and query/update patterns; a hostile database can omit rows. See the [threat model](threat-model.md), [claim limits](decisions/010-security-claim-limits.md), and [mechanical attack method](attack-simulation.md). Avoid substring indexes for low-vocabulary fields.
