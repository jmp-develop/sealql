# SealQL current state and code map

As of 2026-09-29, standard search uses HMAC candidate tokens plus per-row salted exact and occurrence proofs. PostgreSQL completes predicates; count returns one scalar and opens no fields. Lists authenticate only selected encrypted values. AES-256-GCM, row/field/scope AAD binding, and stamp-key derivation are unchanged. Stamp keys use a separate HKDF label; the compact-only token descriptor requires a full rebuild. Decisions [015](decisions/015-database-search-proofs.md) and [016](decisions/016-coarse-exact-bits.md) supersede application predicate verification and the former exact-bit lower bound; the historical decisions remain intact.

The public integration is sealql/drizzle/v0.45. createSealed provides field builders, register, insert/update/upsert, open/openRaw, findMany/count/search, reindex and extraMigrationSql. Parent and companion are ordinary Drizzle tables exported together to drizzle-kit. See the [integration guide](llm-integration.md) and [examples](../examples/standard-consumer.ts). The app supplies a fixed 32-byte global key and optional fixed model keys. There is no key version or DB policy table. Server caches retain fixed derived keys only.

Position predicates allocate forward cursors only after the first candidate fails; Single-literal LIKE with only edge % wildcards uses the equivalent positional predicate; whole-value LIKE also checks compact length. General LIKE searches fixed-width segments between % in order, incorporating underscore widths and anchoring the final segment when required; see [021](decisions/021-like-normalization.md) and [022](decisions/022-like-segment-order.md). Default ID order and explicit ascending ID order emit identical SQL. Finite ID-ordered pages try a prefix of four times the requested limit (minimum 256), then retain its partial matches and continue after its last ID with one ordered candidate → proof → LIMIT fallback. These are internal plan choices, not result or work ceilings; [decision 020](decisions/020-companion-predicate-plans.md) replaces decision 018's proof re-lookups and OR-specific fallback. [Review decision 017](decisions/017-search-proof-review.md) and its [evidence](../bench/results/2026-09-29-r9-review/report-ko.md) record worst-case corrections, write cost and automatic regression coverage.

The companion holds one row per scope/row with tokens and proofs. Exact proofs use salt and a 64-bit stamp. Substring profiles store compact two-character positions only. Singleton and words streams, boundary candidate tokens, wordBoundary/respectWords options and normalizeWords were removed; see [decision 019](decisions/019-compact-only-search.md). Managed writes update ciphertext and affected proofs atomically; partial updates preserve other fields, and deletes cascade. Raw SQL encrypted writes bypass maintenance and can silently omit results. reindex repairs the companion without changing ciphertext, with default batch 1000 and no maximum.

Pure encrypted-predicate count reads only the companion. Parent predicates (where/m.sql), custom JOINs and unfiltered count retain the parent query. WHERE predicates no longer wrap proofs in coalesce; nullable AND/OR still return the same matching rows. Count accepts deadlineMs and signal; unsafe integer results raise LIMIT_EXCEEDED. maxCandidates and count byte/decryption/batch budgets are removed. List byte/time budgets remain optional; batch now counts final matches. There is no implicit result or work ceiling. A finite page defaults to its requested limit per batch. The prefix probe and full fallback both apply final predicates before LIMIT. The app no longer expands candidate batches or verifies condition plaintext. Cursor scope/match/where/order binding and custom JOIN keysets remain; duplicate projected fields in a JOIN use a call-scoped authentication cache. Text and nullable positions are checked with database ordering; UUID/integer positions can be checked locally. Date/timestamp positions are DateStyle-independent.

Exact widths accept explicit 2–32 bits, default16. Low-cardinality fields may choose exact bits2 without substring; exactBitsForPopulation stays unchanged. LIKE requires every normalized literal run to contain at least two characters; singleton literals raise QUERY_TOO_BROAD. Wildcards retain their meanings. Standalone one-character substring queries, encrypted range/sort/aggregates, sealed aliases/self-JOIN, stateful search, posting pages, and bucket research are unsupported.

Companion tokens and compact proof arrays use MAIN storage. Drizzle declares global row uniqueness where valid and covering exact tail keys only for fixed UUID identities; text identities retain narrower indexes. Companion and parent projection queries retain their scope filters; pure encrypted count has no parent scan. The earlier X5 experiment showed no consistent benefit for removing scope filters. Kit generate/migrate/repeated push preserves the schema and additional storage settings. Installation is schema migration, extraMigrationSql (functions/statistics/MAIN), complete sealed.reindex, then new queries. The compact-only token descriptor and removed columns require this full rebuild. A partial rebuild can silently omit rows; there is no persisted completion marker.

Implementation: [src/core](../src/core/) contains crypto, token/proof generation, predicate SQL and cursors; [the Drizzle adapter](../src/adapters/drizzle/v0.45/) owns tables and managed/query operations. The [R9 report](../bench/results/2026-09-29-r9/report-ko.md) records DB/plaintext correctness, writes/reindex, mechanical leakage checks, sorted/random physical-layout measurements, and Node pg/postgres-js/local workerd+pg flows. Hosted Workers/Hyperdrive remains unverified. Final commands are build, check, test, docs:check and test:install. Earlier [native verification](../bench/results/2026-09-27-native-verification/v3/report-ko.md) measures the earlier app-verification engine, not this one.

The position predicate has one fixed COST 1900, calibrated against measured PostgreSQL integer-addition cost. DB functions retain SET search_path=pg_catalog and bounded occurrence loops, but do not validate damaged proof arrays. Apply extraMigrationSql again for the function update; already rebuilt compact-only rows need no additional reindex for decision 020.

Security: the DB receives query value/piece keys, never the root or encryption keys. Disable parameter logging in the database, driver, proxy and telemetry. Token frequency/co-occurrence, normalized lengths, compact position permutations remain visible; observed keys reveal their piece occurrences. A hostile DB can omit rows or falsify predicates even while returning authentic ciphertext. A 64-bit proof collision is possible. Full-record keyless theft resistance is unproven; see the [threat model](threat-model.md) and [mechanical attack method](attack-simulation.md).

General LIKE no longer materializes every piece occurrence or a length-sized frontier. Reapply extraMigrationSql to install the first-position helper and replace the LIKE function; no data rewrite is needed.
