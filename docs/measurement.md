# 측정 규칙

성능·정확성·누출 측정의 공통 규칙이다. 결과는 `bench/results/<날짜>-<주제>/`에 두고, 스크립트와 결과·결정의 대응은 [bench/README.md](../bench/README.md)에 적는다.

## 비교 조건

- 평문, 현재 제품, 후보 방식을 **같은 데이터, 같은 질의, 같은 정렬·LIMIT·투영**으로 비교한다.
- 모든 암호 경로는 최초 실행과 측정 반복마다 **반환 ID 순서와 투영 필드 값이 평문과 같음**을 단언한다. count는 평문 `COUNT`와 같아야 한다. 하나라도 다르면 측정을 멈추고 보고한다.
- **예열 2회**, 경로 순서를 번갈아 **교차 7회**, 지표별 **중앙값**을 낸다. 지표별 중앙값은 서로 합산되지 않을 수 있음을 적는다.
- 첫 호출(콜드 캐시)은 별도로 적는다. OS 캐시를 비우지 않았다면 `cold`라고 부르지 않고 "첫 측정"이라고 쓴다.

## 지표 분리

한 표에 아래를 따로 적는다. 합쳐서 하나의 "DB 시간"으로 쓰지 않는다.

| 지표 | 뜻 |
|---|---|
| SQL 요청~응답 | 클라이언트가 잰 SQL 왕복 합계. 서버 실행 시간만이 아니다 |
| 전체 시간 | API 호출 시작~결과. 토큰·도장 질의 준비와 반환 필드 인증 복호화를 포함 |
| SQL 회수 | 한 호출의 SQL 수 |
| 후보 수 / 반환 행 수 | 토큰 조건에 들어간 행 / DB 도장 판정을 통과해 돌려준 행 |
| 인증 복호화 필드 수 | 실제 `Sealer.open` 호출 수. 계측하지 않았으면 "추정"이라고 적는다 |

- `EXPLAIN (ANALYZE, BUFFERS)`는 별도 1회 실행이다. 다른 반복의 시간에서 빼거나 p50이라고 부르지 않는다.
- 병렬 복호화의 누적 시간은 wall time보다 클 수 있다. 시간 분해에는 wall 구간을 쓴다.
- 측정하지 않은 값은 "측정 안 함", 계산·외삽한 값은 "추정"이라고 적는다. 한 규모의 결과를 1억·10억 행으로 선형 외삽하지 않는다.

## C 로캘 주의

테스트 클러스터는 `C` 로캘이다. `pg_trgm`이 한글 trigram을 만들지 못해(`show_trgm('푸른달') = {}`) 한글 평문 `LIKE`가 전체 스캔이 된다. 그런 행의 "평문 대비 배율"(1 미만 포함)은 **성능 주장에 쓰지 않고** 표에 따로 표시해 판정에서 뺀다. 운영 로캘에서는 평문이 훨씬 빠를 수 있다.

## 데이터

- **일회용 DB만** 쓴다: `127.0.0.1:56439`, 데이터 디렉터리 `.local/pg-test`. 모든 스크립트는 `test/disposable.ts`의 `assertDisposable`과 포트 확인을 먼저 한다. 운영 DB와 5432 포트는 쓰지 않는다.
- 원본 fixture `bench_realistic_100k`(고객·티켓 각 10만 행, 평문 `*_plain`, 정규화 `*_norm`)는 **읽기만** 한다. 후보 형식은 같은 행·값에서 실험 전용 임시 스키마로 파생하고 측정 뒤 제거한다.
- 새 데이터를 **생성**하지 않는다. 평문 생성기는 [bench/fixture/](../bench/fixture/generator.ts)에 재현용으로만 둔다.
- 공개 말뭉치(NSMC `ratings.txt`)는 메모리 시뮬레이션에만 쓴다. DB 적재는 승인되지 않았다.
- 합성 fixture는 템플릿 반복이 많아 오탐과 누출을 과소평가하거나 어휘가 적은 필드에서는 과대평가한다. 누출·오탐 판단은 실제 문장으로도 확인한다.

## 보고

- 결과 보고서는 한국어 1개, 표 중심, 측정 조건과 출처 파일을 표마다 적는다.
- 결론에 "로컬 합성 fixture 결과이며 운영 보장·보안 인증이 아니다"를 적는다.
