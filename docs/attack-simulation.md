# 공격 시뮬레이션으로 보안 판단 검증하기

암호문·검색 토큰의 설계를 바꾸거나 새 보안 주장을 할 때는 **기획 중**(후보 비교)과 **완료 후**(구현 검증)에 이 방법을 쓴다. AI에게 "뚫어 보라"고 맡기지 않는다. 논문에 있는 **재현 가능한 공격 알고리즘**을 돌리고 숫자로 비교한다. 결과는 "최소한 이만큼은 뚫린다"는 하한이지 안전의 증명이 아니다.

## 1. 공격자 조건부터 정한다

| 공격자가 가진 것 | 예 |
|---|---|
| DB 스냅샷·백업 (키 없음) | 토큰 배열, 토큰별 행 수, 암호문 길이, 행 수, FK·평문 컬럼 |
| 원문을 아는 일부 행 | 공격자가 직접 가입·입력한 행, 다른 경로로 샌 기록 (1–10%로 바꿔 가며) |
| 같은 종류의 공개 자료 | 한국어 문장, 이름·주소 분포, 전화번호 형식 |
| (내부자) 쿼리 관찰 | 검색 토큰, 결과 행 수·순서, 반복 검색 |
| 시점이 다른 스냅샷 두 개, WAL | 어떤 행이 언제 바뀌었는지 |

## 2. 상황에 맞는 공격을 고른다

| 상황 | 공격 | 핵심 아이디어 | 참고 |
|---|---|---|---|
| 같은 값이면 같은 토큰 (결정적 토큰) | 빈도 분석 | 토큰 빈도 순위를 공개 자료의 빈도 순위와 맞춤 | Naveed–Kamara–Wright CCS'15 |
| 일부 원문을 앎 | 원문 대조 (count attack) | "이 토큰이 있는 아는 행들"과 "이 조각이 있는 아는 행들"이 같으면 해독 | Cash 외 CCS'15 |
| 한 행에 조각 토큰이 여럿 | 동시출현·일관성 복원 | 함께 나오는 토큰 행렬, 조각끼리의 논리 관계(ab·bc → a_c)로 해독을 넓히고 문자열을 이어 붙임 | IKK(NDSS'12), Kroll–Steinmetzer 2014 (bigram Bloom) |
| 짧거나 형식이 정해진 필드 | 길이·형식 추론 | 암호문 길이와 토큰 수로 후보를 줄이고 형식(전화, 생일)으로 전수 대입 | — |
| 토큰 계산 기능을 쓸 수 있음 (앱 탈취) | 사전 대입 | 후보 값의 토큰을 직접 만들어 대조. 값의 종류가 적을수록 치명적 | Paragonie blind index |
| 쿼리를 관찰 | 검색어·결과 복원 | 결과 크기(volume), 반복 패턴, 순서로 검색어와 값을 추정 | GLMP·volume 공격 계열 |
| 스냅샷이 여러 개 | 변경 추적 | 두 시점의 토큰과 행을 비교해 갱신 내용을 연결 | [위협 모델](threat-model.md) T2 |

## 3. 측정 규칙

- **데이터:** 합성 템플릿 데이터는 자연어의 누출과 오탐을 대표하지 못한다(조각 다양성이 적어 오탐은 과소평가하고, 어휘가 적은 필드의 누출은 크게 나온다). 같은 종류의 실제 공개 자료를 함께 쓴다(예: NSMC 한국어 리뷰). 공격자의 참고 자료와 피해 데이터는 서로 겹치지 않게 나눈다.
- **비교:** 현재 방식과 후보 방식을 같은 공격, 같은 데이터, 같은 시드로 돌린다. 공격자 지식(아는 행 비율 등)을 여러 단계로 바꾼다.
- **지표:** 해독된 조각 비율(등장 기준), 대부분(80%+) 해독된 행 비율, 짧은 필드의 값 완전 복원 비율을 낸다. 같은 표에 검색 오탐과 속도도 함께 둔다.
- **기록:** 스크립트는 `bench/`, 결과는 `bench/results/`에 둔다. 결론에는 "사용한 공격 목록 = 하한"과 쓰지 않은 공격을 적는다.
- **현재 예:** [`competitor-sim/attacks.ts`](../bench/competitor-sim/attacks.ts)(빈도·알려진 원문·선택 삽입), [`dummy-sim/run.ts`](../bench/dummy-sim/run.ts)(더미 인지 전화 복원), [`attack-extra/backup.ts`](../bench/attack-extra/backup.ts)(키 없는 백업), [`final-review/r9-impl/attack.ts`](../bench/final-review/r9-impl/attack.ts)(현재 토큰 공격), [`lasthour/m1-astra/observation.ts`](../bench/lasthour/m1-astra/observation.ts)(쿼리 관찰). 각 결과는 대응하는 `bench/results/` 보고서에 조건과 한계를 기록한다.
