# 004. 조각 토큰 16비트, 조각 구성, 정규화

- 상태: 확정 (2026-09-27)
- 일부 대체: exact 최소 비트 수는 [016](016-coarse-exact-bits.md)으로 대체됐다. 아래 본문은 당시 결정 기록이다.

## 결정

- **부분 검색 토큰은 16비트로 고정한다.** 토큰 값은 `(scope 32비트 HMAC prefix << 32) | 값 HMAC 상위 16비트`의 부호 있는 64비트 정수다.
- **정확 일치 토큰**은 필드별 `bits`(기본 16, 8–32)를 쓴다. `exactBitsForPopulation(P)`가 예상 최대 고유값 수 P에서 `floor(log2 P) − 1`(8–32로 제한)을 계산한다(AWS·CipherSweet 공식).
- **정규화**(토큰에 새겨지므로 바꾸면 재색인): NFC, 전각 ASCII·숫자 → 반각, ASCII 대문자 → 소문자. 조각 스트림은 공백을 제거한 문자열 기준, 단어 경계는 공백을 하나로 접은 문자열 기준이다.
- **조각 구성**: 인접 2글자 조각 + 값 시작·끝 조각(항상) + 건너뛴 조각(기본 켬, [005](005-skip-grams-default-on.md)) + 단어 경계 조각(스키마 옵션 `wordBoundary`).
- 시작·끝·단어 경계 표식은 텍스트 문자가 아니라 **HMAC 입력 프레임의 조각 종류 필드**로 분리한다. 평문의 어떤 문자도 표식을 흉내 낼 수 없다.
- 최소 검색 길이는 정규화 후 **2글자**다. 1글자와 빈 검색어는 `QUERY_TOO_BROAD`로 거부한다.

## 근거

알려진 원문 공격(공격자가 피해 행 일부의 원문을 앎) 기준, "모르는 행 중 조각 80% 이상이 해독된 행" 비율이다. 공개 한국어 리뷰(NSMC)의 메모리 시뮬레이션이다.

| 조건 | 16비트 | 17비트 | 20비트 | 출처 |
|---|---:|---:|---:|---|
| 옛 벤치 토큰(FNV-1a 절단), 10만 행, 인접만, 5% | 0.7% | 3.5% | 35.5% | [scale-ko.md](../../bench/results/2026-09-27-layout-attack/scale-ko.md)(16비트 재현), 17·20비트는 원 기록 삭제·수치만 보존 |
| **제품 HMAC 토큰**, 10만 행, 인접만, 5% | **3.64%** | 11.53% | 43.06% | [bits-ko.md](../../bench/results/2026-09-27-layout-attack/bits-ko.md) |
| 제품 토큰, 10만 행, 인접+시작·끝+단어 경계, 5% | 1.19% | 7.06% | 70.09% | 같은 파일 |

- **정정:** 16비트의 "0.7%"는 옛 벤치 토큰과 옛 알려진 행 추첨의 값이다. 제품 HMAC 토큰에서는 **3.64%**다.
- 제품 토큰에서도 **16 < 17 < 20비트** 순서는 8개 조건(구성 2 × 규모 2 × 원문 1%·5%) 모두에서 유지됐다. 결정은 유지한다.
- 14·15비트는 누출이 더 적었다(예: 10만 행, 인접+시작·끝+단어 경계, 5%에서 14비트 0.00%, 15비트 0.04%). 드문 검색어의 오탐은 측정하지 않았으므로 바꾸지 않는다.
- 비트를 늘려도 오탐은 거의 줄지 않는다. 긴 메모 10만 행의 중간 3글자 검색 후보/정답은 16비트 ×1.381, 32비트 ×1.351이다 ([corpus-sim3-long.json](../../bench/results/standard-review-2026-09-26/corpus-sim3-long.json)). 대신 희귀 토큰 보유 행이 17.6% → 88.7%로 는다. 오탐은 비트가 아니라 조각 구성으로 줄인다.
- **"작은 테이블이 더 샌다"는 가설은 반증됐다.** 인접만·5%에서 피해 행 5천/2만/5만/10만의 80%+ 해독은 2.51/6.26/7.41/3.64%로 단조 관계가 없었다 ([scale-ko.md](../../bench/results/2026-09-27-layout-attack/scale-ko.md)).
- 시작·끝 조각: 필드 시작 자동완성 후보/정답 **×30 → ×1.5**. 단어 경계 조각: 두 단어 검색 **×1.86 → ×1.51**. 희귀 토큰 보유 행은 18.6 → 17.6%로 늘지 않았다 ([corpus-sim2.json](../../bench/results/standard-review-2026-09-26/corpus-sim2.json)).
- 표식을 리터럴 문자(`^`)로 두면 실제 리뷰의 `^^`와 충돌했다. 그래서 HMAC 입력 구조로 분리했다.
- NFC 강제는 macOS NFD 입력의 검색 누락을 막는다(Apple QA1173, ICU, Lucene). 입력 경계 테스트에서 NFC/NFD 한글, 전각, 대소문자, 연속 공백이 일치했다 ([V1 검증](../../bench/results/2026-09-27-core-verification/v1/report-ko.md)).
- 정확 일치 16비트 고정은 고유값 10만에서 버킷 78%가 공유되어 0건 조회도 후보를 복호화한다. 규모에 따라 오탐이 늘므로 필드별 bits를 둔다 ([token-leakage.json](../../bench/results/standard-review-2026-09-26/token-leakage.json)).

## 기각안

| 안 | 기각 이유 |
|---|---|
| 조각 토큰 17비트("16–17비트") 권장 | 알려진 원문 공격에 확실히 약해지고 검색 이득이 거의 없다. 권장을 철회했다 |
| 규모에 맞춰 조각 비트를 늘림 | 누출 급증. 규모 규칙은 정확 일치 토큰에만 적용 |
| 2–4글자 n-gram | 누출 폭증([001](001-search-hmac-pieces-gin-verify.md)) |
| 1글자 검색 | 지원하지 않는다(사용자 결정) |
| 표식을 텍스트 문자로 표현 | 평문 문자와 충돌 |
| 숫자·ASCII 필드 3글자 조각, 필드 구조 분해(끝 4자리, 도메인) | 최소 검색 길이 증가, 고유값이 적은 조각이 누출 취약점이 된다. 보류 |

## 대체 관계
