# 020 — 검색 표에서 판정하고 마지막에 투영

2026-09-29. [018](018-identity-order-page-plans.md)의 fallback 재조회·최상위 OR 전용 경로를 대체한다. [019](019-compact-only-search.md)의 compact-only 저장 형식과 공개 API는 그대로다.

## 결정

순수 암호화 조건의 count는 검색 표만 읽는다. `where`, `m.sql`, 사용자 JOIN처럼 부모 칸을 참조하는 질의는 부모 조건을 유지한다. 조건 없는 count도 검색 값이 모두 NULL인 부모 행을 포함해야 하므로 부모를 센다. 목록의 암호화 판정은 검색 표에서 끝내고 부모는 결과 투영에 연결한다. 기본 ID순과 명시한 ID 오름차순은 같은 경로이며, 연산자나 Boolean 최상위 노드로 실행 방식을 나누지 않는다.

WHERE 아래 양의 AND/OR 식에서는 NULL과 false 모두 행을 제외한다. 불필요한 `coalesce(proof,false)`를 제거하여 exact equality의 선택도가 계획기에 보이게 한다. 유한 ID순 목록은 quick를 유지하고, fallback은 연구와 같은 후보 ID순 → 판정 → LIMIT을 사용한다. 표본은 scope와 keyset만 적용한 완전한 ID 앞부분이다. quick가 부족하면 그 앞부분을 모두 판정했으므로 찾은 결과를 보존하고, fallback은 표본 마지막 ID 뒤에서 남은 개수만 찾는다. proof 열을 다시 찾는 lateral 조회와 OR 전용 fallback을 없앤다.

위치 판정은 첫 창 첫 후보에서 성공하면 커서 배열을 만들지 않는다. 첫 불일치 뒤에만 배열을 만들고 이후 각 창의 순번을 앞으로 이동시킨다. 작은 배열의 native 탐색과 큰 배열의 이진 탐색을 유지하여 4,002자 근접 불일치에서 반복 전체 스캔으로 돌아가지 않는다. 첫 창과 후속 창의 순번은 정규화 길이 이하로 제한한다. 쿼리 프로그램은 앱에서 검증하고 proof는 관리형 쓰기에서 만들므로 함수 내부의 손상 입력·역행 검사는 제거한다. 악성 DB의 판정·완전성은 원래 보장하지 않으며 반환 암호문의 AES-GCM/AAD 인증은 그대로다.

`SET search_path=pg_catalog`, MAIN, exact 꼬리 키 색인은 유지한다. 함수·연산자를 완전 한정한 no-SET 변형은 같은 배열에서 독립적인 이득을 보이지 않았다. 여러 물리 clone을 섞은 측정에서 나타난 함수 변형의 목록 2배 개선은 원본 재실행도 같은 속도로 빨라지는 캐시 효과가 섞여 있어 채택 근거로 쓰지 않는다.

원인은 [7조건 표](../../bench/results/2026-09-29-final-impl/root-causes-ko.md)에 분리했다. 같은 배열의 함수 비교와 실제 질의 계획은 [채택 검증](../../bench/results/2026-09-29-final-impl/adopt-report-ko.md)에 기록한다. 최종 전체 조건 판정은 독립 검증자가 같은 세션의 평문·연구 최종안·제품 3경로로 수행한다. 로컬 fixture 결과는 운영 성능이나 보안 인증이 아니다.

## 대체 관계

018의 fallback 재조회·OR 분기와 017의 손상 검사 부분을 대체한다. 017의 전진 커서와 긴 근접 불일치 교정은 유지하며 019의 compact-only 형식은 바꾸지 않는다.

이 변경은 SQL 생성과 DB 함수만 바꾼다. compact-only 스키마로 이미 완전히 재색인했다면 `extraMigrationSql`의 함수를 다시 적용하면 되고, 이 변경만을 위한 암호문·토큰 재작성은 필요 없다. 이전 singleton/words 형식에서 오는 경우에는 결정 019의 전체 schema·함수·reindex 순서를 반드시 따른다.
